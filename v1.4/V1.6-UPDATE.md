# Moshaver v1.6.0 — Student and advisor operations release

## Architecture

The release keeps the existing dependency-light Node.js HTTP router, SQLite migrations, cookie sessions, CSRF checks, SSE event log, and static Persian RTL admin/student PWAs. New aggregation logic lives in `backend/src/services/student-dashboard.service.js`; route handlers remain thin.

## Database migrations

- `004_student_first_release`: adds explicit active/inactive/archived account state, archive metadata, durable learning-review history, study outcome fields, and bounded-query indexes.
- `005_study_pause`: safely adds persisted pause state for databases that may already have applied migration 004 during staged rollout.
- Migrations are additive. Back up the SQLite file and start the backend normally; startup applies unapplied migrations. Do not replace or reset an existing database.

## API changes

- `GET /api/v1/student/today`: bounded Today payload with current/next task, progress, due reviews with reason codes, next exam, unread totals, and active session.
- `GET /api/v1/student/progress/weekly`
- `GET /api/v1/student/performance/topics`
- `GET /api/v1/learning/items/:id/reviews`
- `POST /api/v1/study-sessions/:id/pause|resume`
- `GET /api/v1/admin/attention`
- `GET /api/v1/admin/students/:id/progress/weekly`
- `GET /api/v1/admin/students/:id/performance/topics`
- `GET /api/v1/admin/students/:id/learning/:itemId/reviews`
- `POST /api/v1/admin/students/:id/deactivate|activate|force-logout`
- `POST /api/v1/admin/students/:id/restore` restores an archived account and its preserved history.
- `GET /api/v1/admin/realtime/students` returns a bounded all-student snapshot, normalized state/freshness, summary counters, and the latest cross-student timeline.
- `GET /api/v1/admin/system/database` returns safe health metadata without exposing filesystem paths.
- `POST /api/v1/admin/system/database-backup` creates and streams an integrity-checked SQLite snapshot. It is admin-only, CSRF protected, rate limited, audited, and removes temporary files after transfer.
- `DELETE /api/v1/admin/students/:id` now archives while preserving educational history.
- `GET /api/v1/admin/students` is paginated and returns `{items,total,limit,offset,hasMore}`. It supports `search`, `status`, `limit`, and `offset`.

## Realtime events

Existing educational SSE events remain compatible. Study sessions now additionally emit `study.paused` and `study.resumed`; completion remains `study.finished`. Learning reviews emit `learning.reviewed` and persist their full scheduling transition.

## Admin app

- One-time credentials now have show/hide and separate username/password/both copy actions.
- Student deactivation and archival are distinct; both revoke sessions, and archived accounts have an explicit restore workflow.
- Student cockpit concurrently loads profile, learning queue, attempts, weekly progress, and topic performance.
- Weak-topic cards provide immediate review and message actions.
- Needs Attention lists explain overdue review, low exam accuracy, and inactivity rules and opens the selected cockpit directly.
- Live Operations shows every active student with online/studying/paused/exam/offline states, freshness, current context, filters, timers, quick cockpit/message actions, and a shared activity timeline.
- System & Security displays database/service health and downloads safe SQLite snapshots with clear progress and result feedback.
- Production HTML loads generated `admin-app/css/app.css`; edit the ordered sources in `admin-app/css/src/` and rebuild with `node scripts/build-css.mjs`.

## Student app

- Today uses the single bounded `/student/today` startup payload and stores only an explicit safe Today snapshot for offline display support.
- Focus mode supports persisted pause/resume and captures tests completed at finish.
- Guided review uses understandable 1–5 labels, shows recommendation reasons, advances to the next due item, and exposes durable review history.
- Exam history, question review, contextual learning creation, chat, CSS source generation, RTL, dark mode, and reduced-motion behavior remain compatible.

### Typography and exam workspace

- Student typography uses one scale in `css/src/01-tokens.css`: 12px captions, 13px secondary text, 14px body/buttons, 16px important text and form controls, and 20–24px page titles.
- Meaningful 7–11px declarations were removed from all source layers. Persian body copy uses relaxed line height while RTL/LTR timers and scores remain isolated.
- The exam task still opens the exam detail/readiness modal first. Starting or resuming then opens a full-height runner with persistent answers, persistent flagged questions, a numbered question map, remaining-time warning, previous/next navigation, and an in-app final review instead of a browser confirm dialog.
- Syllabus readiness controls now read the nested progress state correctly, and exam cards are actionable immediately while readiness loads.

### Date-relative demo week

`npm run seed:demo-week` idempotently creates or updates a seven-day plan beginning on the current date. It adds 49 detailed activities across study, review, test, class, meal, prayer, break, and exam task types; a linked midweek practice; a linked end-of-week exam; five syllabus groups; and 12 explained questions in each quiz.

### Unified local launcher

Run the complete stack from `v1.4/`:

```bash
./run-local.sh
```

The launcher refreshes the demo week, reuses healthy processes on ports 4000/8080/8081, starts missing services, stores logs under `.run/`, and only stops child processes that it started.

## Deployment

1. Download a verified backup from Admin → System & Security.
2. Deploy backend, admin app, and student app together with `APP_VERSION=1.6.0`.
3. Start the backend once and verify `/ready` so migrations 004 and 005 are applied.
4. Purge only old static PWA caches if the normal service-worker update prompt is not accepted; authenticated API responses are not service-worker cached.
5. Run the validation commands documented in the release handoff before production promotion.

## Known limits

- Risk rules are deliberately deterministic and conservative; they are not predictive AI.
- Topic trend labels require at least five recorded answers; smaller samples report `Not Enough Data`.
- Advisor assignment is stored for forward compatibility but the current single-advisor UI does not expose a selector.
