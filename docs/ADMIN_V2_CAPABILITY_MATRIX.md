# Admin v2 capability matrix

Last source audit: 2026-09-06

Scope: `admin-v2` consumers and canonical `backend-v2` `/api/v2` contracts on `feat/v2-parity-completion`.

This is the current source of truth for Admin v2 capability coverage. Historical migration audits remain useful evidence, but their old gap labels do not override this matrix.

Status meanings: **Complete** is implemented in both layers and covered by an automated or disposable integration check; **Partial** is implemented but has a named verification or UX gap; **Missing** has no usable end-to-end workflow; **Deprecated** is retained only as a compatibility alias.

## Current release boundaries

- Unit/component tests, the scoped core-logic coverage gate, accessibility smoke, production build, and parity gate are automated.
- Backend role isolation and canonical workflows are exercised against a disposable SQLite database.
- Real VAPID-backed Web Push delivery remains **Partial** until received in a production-like browser.
- Database restore remains **Partial** for target acceptance and must only be tested with a disposable database.
- Historical v1.6 retirement still requires a complete browser smoke suite.
